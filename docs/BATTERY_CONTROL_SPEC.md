# Pharos 电池充电管理与控制规格书 (Battery Control Specification)

> 本文档汇总了在 macOS Sequoia 15 上实现接近 macOS Tahoe 原生充电上限控制的全部愿景、核心目标、参考项目分析、硬件与固件接口、安全约束守则（最高优先级原则）以及后续迭代清单，供所有开发贡献者与 AI Agent 遵循与参考。

---

## 一、项目愿景与定位

在 macOS 原生轻量开源工具 **Pharos** 中新增电池充电管理模块，目标是在 **macOS Sequoia 15** 上实现接近 macOS Tahoe 原生充电上限功能（例如 80% 上限）的使用体验：
1. 用户可以自主设置电池充电上限（例如 80%），由 Pharos 根据 Mac 的硬件、固件和系统接口能力，选择合适且安全的硬件控制方式，避免设备长期处于 100% 满电高压高热状态。
2. **复刻 macOS 15 官方充电管理与“小插头”状态**：在系统确实进入充电管理状态时，完美保留系统原生电池状态反馈——菜单栏电池图标从普通闪电图标转变为“小插头”图标（`Not Charging`），系统电源描述显示为“电源：电源适配器 · 电池未在充电”。
3. **真实充电控制而非仅视觉模拟**：不仅追求图标变化，更通过实测验证硬件真实电流（0 mA）与直通供电状态，确保电池真正停止充电。
4. **定位原则**：我们是在扩展 macOS 的充电管理控制能力，而不是取代 macOS 的电池管理系统。宁可某项功能暂不提供，也绝不能破坏系统原有充电节奏或增加电池损耗风险。

## 三、硬件与固件接口深度分析（基于 Apple Silicon M3 Pro 实测）

在搭载 Apple Silicon（M3 Pro，设备标识 `Mac15,6`，系统 macOS 15.6.1）上的底层探测结果与控制策略：

| SMC 寄存器 | 数据类型 | 存在性 | 说明与使用规范 |
| :--- | :--- | :--- | :--- |
| `CHTE` | `ui32` (4 字节) | **存在 (True)** | **Apple Silicon 核心硬件限充寄存器**。写入 `[0x01, 0x00, 0x00, 0x00]` 立即阻断充电流（电芯电流变为 0 mA）；写入 `[0x00, 0x00, 0x00, 0x00]` 恢复充电。外接电源持续为整机主板供电，**绝不切断适配器**。 |
| `CH0C` | `hex_` (1 字节) | **存在 (True)** | 备用充电阻断寄存器。在部分机型上备用：写入 `[0x01]` 阻断充电，写入 `[0x00]` 允许充电。 |
| `ACLC` | `ui8` (1 字节) | **存在 (True)** | MagSafe 3 LED 指示灯颜色控制寄存器。`0x00` 为系统控制，`0x04` 为黄色/橙色常亮，`0x03` 为绿色常亮。**注意：绝不可写入 `0x01`（关闭灯光）**。在 macOS 15 原生“未在充电”状态下，MagSafe 应保持原生黄色或系统默认。 |
| `CHIE` | `hex_` (1 字节) | **存在 (True)** | **适配器旁路（切断外接供电）寄存器。严禁在限充中写入 `0x08`！** 写入 `0x08` 会物理断开适配器输入，让电脑瞬间转为纯电池供电，导致屏幕背光闪烁、电池高频震荡放电。必须始终保持为 `0x00`。 |
| `BCLM` | `ui8` | **不存在 (False)** | Intel 架构旧款 Mac 的充电上限寄存器，Apple Silicon 上已彻底弃用，不可盲目写入。 |

## 四、最高优先级原则（安全与开发守则）

任何对电池模块的代码改动，**必须无条件遵守以下安全原则**：

1. **保护原生充电策略与电池安全（最高原则）**：
   - 任何功能实现都不能以牺牲系统稳定性或电池安全为代价。
   - 保留原生充电节奏，不随意干预系统的充电速率、温度管理及电池保护策略。
   - **不强制对抗系统策略**：不得为了维持设定的电量上限而反复强制开启或关闭充电，不得持续覆盖系统的充电安全保护。
2. **纯粹直通供电，严禁强制断电放电**：
   - 限制充电只能通过阻断充电流（`CHTE`）实现，**绝对不得通过断开外接适配器（`CHIE`）来强行放电**。
   - 当用户在 100% 满电时开启 80% 限充，正确做法是立即阻断充电流（进入小插头模式，外接电源直接供电，0 mA 电流），等待日常携带使用或自然消耗至 80% 后自动在此限位保持。绝不可为了迎合数字而切断电源去放电。
3. **优先采用可逆控制与心跳安全回退**：
   - 特权守护程序 `pharos-battd` 采用 15 秒心跳安全超时。若 Pharos 主程序退出、崩溃或未在 15 秒内发送心跳，守护进程必须自动释放全部 SMC 锁（`releaseHardwareLocked()`），将控制权无缝归还 macOS 系统。
   - 守护进程收到退出信号（SIGTERM / SIGINT）或被卸载时，必须在退出前先归还控制权。
4. **不以电量数字代替真实硬件状态**：
   - 不能仅凭电池百分比判断控制成功，必须结合 `AppleSmartBattery` 的 `Amperage`（电流）、`IsCharging`、`ExternalConnected` 及 `IOPS` 状态验证实际充电行为。
5. **合盖睡眠与唤醒兼容**：
   - 达到限充（holding）状态时，必须允许系统正常睡眠（`allowSleep`），不得在达到上限后无限阻止系统睡眠。
   - 仅在用户显式要求“立即充满电”且电量尚未达到 100% 时，才可持有系统防睡眠断言（`preventSleep`）。
6. **严格遵守项目核心守则 (`AGENTS.md`)**：
   - 100% 纯 Apple 原生 Swift 编写（SwiftUI, AppKit, Foundation, IOKit），零第三方依赖。
   - 严格 ARC 内存安全，所有长期持有的闭包必须加 `[weak self]`。
   - 业务逻辑与安全策略全部在 `Sources/PharosCore/`（纯逻辑、无 UI 依赖、100% 单元测试覆盖）。
   - 全部用户可见文案统一走 `L10n.swift`，必须提供中英双语。

## 六、待实施体验优化清单

1. **[P0] 增加「交由系统管理」显式控制按钮**：
   - 用户可随时点击将充电控制模式重置为 `system`，即刻释放硬件 SMC 锁，回归 macOS 原生电池管理。
2. **[P0] 解决组件更新时的瞬态网络报错**：
   - 特权组件重新安装/更新后，launchd 重启守护程序存在 200~400ms 窗口，通信层增加重试机制（Retry with Backoff），并在安装完成后延迟 300ms 探测，消除“发送指令失败”的瞬态报错。
3. **[P1] 增强用户点击 80% 后的即时接管感知**：
   - 快速挡位（80%、85% 等）根据当前生效的设定呈现高亮胶囊样式；
   - 状态栏显式展示控制状态徽标：`● Pharos 硬件限充生效中` vs `○ macOS 原生托管中`；
   - 显式展示当前电芯电流 `0 mA` 及“电源适配器直通供电”状态。
4. **[P1] MagSafe 指示灯对齐原生行为**：
   - 在限充小插头状态下，保持系统默认灯光或黄色/橙色常亮灯，绝不关闭灯光，绝不切断适配器输入。
