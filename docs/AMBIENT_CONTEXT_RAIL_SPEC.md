# Pharos 伴随式右侧微岛 (Ambient Context Rail) 规格说明书
## —— macOS 控制中心式分块悬浮架构 (Control Center Modular Bento Cards)

> **修订版本**：v2.2（新增「三维安全区域与呼吸间距体系」：中间画布与右卡安全隔离带、滚动条避让及窗口物理边界）  
> **文档定位**：指导 Pharos macOS 客户端在宽屏/全屏状态下的右侧空白区域利用方案。采用「低存在感 · 独立分块圆角矩形（Control Center Bento Cards）」形态，为全屏工作流提供层次分明、通透轻盈、即看即得的上下文辅助。

## 一、 设计哲学与系统交互原则

### 1.1 为什么拆分为“类似控制中心的分块矩形”？
1. **打破呆滞对称，建立主从韵律（Visual Asymmetry & Hierarchy）**：
   - **左侧导航岛（236pt）**：作为全局骨架，保持完整的长条通高浮岛，代表“坚固、稳定、全局入口”。
   - **右侧伴随岛（260pt）**：切分为 **2~3 个大小不一、形态各异的悬浮圆角矩形小组件（Widgets）**，代表“动态、灵活、即看即走的上下文模块”。
   - 避免了“左右两根大门神柱子夹着中间内容”的压抑感，左实右灵，视觉层次拉开。
2. **通透感与呼吸空间（Breathing Room）**：
   - 卡片与卡片之间留出 **8~10pt** 的间距，窗口底层的优雅渐变背景自然穿透卡片缝隙，彻底消除右侧的堵塞感，完美实现“存在感低、不抢戏”的核心诉求。
3. **内容高度自适应，告别空洞（Natural Content Fit）**：
   - 信息精简的页面展示 2 个小巧卡片，下方自然留白；信息丰富的页面组合 3 个卡片。不再需要生硬拉伸填满整个窗口高度。

### 1.2 响应式显隐规则（Responsive Breakpoints）
- **紧凑窗口（宽度 < 1180px，如默认 1024×720）**：
  - 右侧卡片群**完全收起（隐藏）**，不占渲染与布局资源。
  - 主内容区域（`PharosPage`）自适应占据除左侧导航岛外的全部空间。
- **宽屏/全屏（宽度 ≥ 1180px）**：
  - 右侧独立卡片群平滑淡入并轻微上浮展开，总宽度为 **260pt**。
- **用户自由控制**：
  - 窗口右上角提供微型折叠按钮（`sidebar.trailing`），状态持久化至 `@AppStorage("pharos.showInspector")`。

## 二、 三维安全区域与间距体系（Safe Margins & Spacing Architecture）

为确保右侧分块卡片与中间内容画布不发生视觉挤压、拥挤打架或遮挡滚动条，严格执行以下**全维度安全边距规范**：

```
┌───────────────────────────────────────────────────────────────────────────────┐
│                               窗口物理边界                                    │
│  ←10pt→ ┌──────────────┐ ←14pt→ ┌─────────────────────┐ ←16pt→ ┌───────────┐  │
│  外边距 │              │ 导航与 │                     │ 中间与 │           │  │
│         │ 左侧导航岛   │ 中间区 │  中间主内容画布     │ 右卡片 │ 右侧卡片群│  │
│         │  (236pt)     │ 隔离带 │   (Fluid Flex)      │ 安全区 │  (260pt)  │  │
│         │              │        │                     │ [Safe] │           │  │
│         │              │        │                     │ [Gutter│ ┌───────┐ │  │
│         │              │        │                     │  16pt ]│ │Tile A │ │  │
│         │              │        │                     │        │ └───────┘ │  │
│         │              │        │                     │        │  ↕ (8pt)  │  │
│         │              │        │                     │        │ ┌───────┐ │  │
│         │              │        │                     │        │ │Tile B │ │  │
│         │              │        │ [滚动条安全避让区]  │        │ └───────┘ │  │
│         └──────────────┘        └─────────────────────┘        └───────────┘  │
│  ←10pt安全外距                                                   10pt安全外距→│
└───────────────────────────────────────────────────────────────────────────────┘
```

### 2.1 中间画布与右侧卡片的安全隔离带（Center-to-Right Safe Gutter）
- **物理间距**：`HStack` 容器中的 `spacing` 统一设置为 **`16pt`**（比左岛与中间的 14pt 稍大 2pt，强化右侧小组件群的浮岛独立性）。
- **禁止贴边**：中间画布与右侧卡片之间必须保留清爽的空隙，窗口背景渐变完整纵贯穿透，确保视线移动时界限分明、毫无压迫感。

### 2.2 滚动条避让与手势安全区（Scrollbar Inset Safety）
- **中间内容区滚动条隔离**：
  - 中间 `detailView` 内部滚动时，其滚动指示器（Scroll Indicator）与右侧卡片之间预留 **`10~12pt`** 的水平缓冲。
  - 严禁出现“中间滚动条直接贴在右侧卡片左边缘”的粗糙视觉瑕疵。
- **右侧卡片群滚动策略**：
  - 右侧伴随岛由于只有 2~3 个精简模块，优先采用自适应高度；
  - 若在小屏幕高度下必须滚动，右侧容器统一采用 `.scrollIndicators(.hidden)`，避免右侧出现第二条滚动条造成“双滚动条并立”的混乱。

### 2.3 窗口四向外围安全内边距（Outer Window Margins）
- **左 / 右外边距**：左右两侧严格保持像素级对称的 **`10pt`** 窗口内边距（`padding(10)`）。
- **顶部安全高度**：
  - 顶部预留 **`38pt`** 安全高度，与左侧红绿灯交通灯基准线（Traffic Light Base）横向对齐，保证全屏下卡片顶部与左侧内容保持在同一水平视线线上。
- **底部安全缓冲**：底部预留 **`12~14pt`**，卡片底边不直接触碰窗口物理底线，避免悬浮感被截断。

## 三、 Bento 便当盒美学组合法则（Composition Aesthetics）

遵循 Apple Bento 模块化排版体系，保证“大小不一，但整体组合极富美感与秩序”：

```
                【Bento Grid 美学版式组合范式】

   范式 A：经典渐进流           范式 B：双子并列矩阵          范式 C：双雄均衡流
  (Classic Cadence)           (Twin-Tile Matrix)          (Balanced Dual)

┌───────────────────────┐   ┌───────────┐ ┌───────────┐   ┌───────────────────────┐
│ Card A: 脉搏微条 (48) │   │ Tile A(68)│ │ Tile B(68)│   │ Card A: 深度指标(125) │
└───────────────────────┘   └───────────┘ └───────────┘   │ (如散热安全裕度刻度)  │
           ↕ (8pt)                     ↕ (8pt)            └───────────────────────┘
┌───────────────────────┐   ┌───────────────────────┐                ↕ (8pt)
│                       │   │                       │   ┌───────────────────────┐
│ Card B: 主力大卡(160) │   │ Card C: 主力大卡(155) │   │ Card B: 深度指标(125) │
│ (核心图表/联调地址)   │   │ (深度图表/操作中枢)   │   │ (如实时充放电能效仪)  │
│                       │   │                       │   └───────────────────────┘
└───────────────────────┘   └───────────────────────┘                ↕ (8pt)
           ↕ (8pt)                     ↕ (8pt)            ┌───────────────────────┐
┌───────────────────────┐   ┌───────────────────────┐   │ Card C: 快捷小胶囊(44)│
│ Card C: 快捷小条 (72) │   │ Card D: 快捷小条 (68) │   └───────────────────────┘
└───────────────────────┘   └───────────────────────┘
```

### 3.1 网格与模数体系（Grid & Module Tokens）
- **外框总宽**：固定 `260pt`，卡片间垂直间距统一为 `8pt`（Apple 8pt 网格基准）。
- **形态 1：单行通宽卡片（Full-width Cards，宽 260pt）**
  - **Mini 胶囊卡（高度 44~52pt）**：单行结构，承载状态点、极短结论或单按钮。
  - **Medium 中型卡（高度 70~95pt）**：适合承载 2 行短信息 + 1 个操作药丸。
  - **Hero 主力大卡（高度 140~180pt）**：多行结构，承载分段比率条、多级列表或跳板清单。
- **形态 2：1:1 并列双子微方块（Twin Tiles，每块宽 126pt，间距 8pt，高约 64~72pt）**
  - 类似 macOS 控制中心中的 Wi-Fi 与蓝牙并排方块。
  - 适合放置两个平级的关键数字（例如：左边放「活跃端口数 5」，右边放「暴露端口数 1」；或左边「芯片温度 48°C」，右边「功耗 8.4W」）。
  - **美感价值**：瞬间打破单向竖直排列的沉闷感，给右侧界面注入活泼而严谨的瑞士平面设计美感。

### 3.2 视觉材质与微动效（Surface Styling）
- **连续圆角（Squircle）**：全系统统一采用 `RoundedRectangle(cornerRadius: 14, style: .continuous)`（并列小方块也保持 14pt 圆角，保证曲率系统连贯）。
- **呼吸式层叠投影**：
  - 接触阴影：`shadow(color: Color.black.opacity(0.03), radius: 2, x: 0, y: 1)`
  - 环境阴影：`shadow(color: Color.black.opacity(0.06), radius: 8, x: 0, y: 3)`
- **微描边**：`stroke(PharosColor.separator.opacity(0.3), lineWidth: 0.5)`。
- **悬停质感**：鼠标移动到可点击卡片或 Action Pill 时，触发 `0.15s` 微弱亮起动效，绝不突兀。
